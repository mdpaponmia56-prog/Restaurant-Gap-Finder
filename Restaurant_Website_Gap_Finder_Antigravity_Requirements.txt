# 1. PRODUCT OVERVIEW

## Product Name

**Restaurant Website Gap Finder**

## Purpose

A production B2B lead-generation and research platform that discovers real restaurants in user-selected locations, qualifies them using configurable Google Maps criteria, verifies whether they have an official website, enriches public business information, deduplicates records, scores digital opportunity, stores source evidence, and exports qualified leads.

## Primary Users

- Web developers
- Web agencies
- Digital marketing agencies
- Restaurant technology consultants
- B2B sales/research teams

## Core Problem

Finding restaurants that are legitimate, active, sufficiently established, and digitally underserved is time-consuming.

The application automates:

DISCOVERY → QUALIFICATION → WEBSITE VERIFICATION → ENRICHMENT → DEDUPLICATION → SCORING → STORAGE → EXPORT

# 5. WEBSITE GAP DETECTION

Google not returning a website does NOT automatically prove that a restaurant has no website.

The system must independently verify website status.

Check:

- Google website URI
- Search results
- Domain availability/reachability
- Restaurant name
- Address
- Phone
- Branding
- Menu
- About/contact information
- Structured data
- Social links
- Business identity

Website statuses:

- NO_WEBSITE_VERIFIED
- NO_WEBSITE_PROBABLE
- HAS_OFFICIAL_WEBSITE
- SOCIAL_ONLY
- MARKETPLACE_ONLY
- UNKNOWN

Social pages and third-party platforms do NOT count as official websites by themselves.

Examples:

- Facebook = not an official website
- Instagram = not an official website
- Yelp = not an official website
- TripAdvisor = not an official website
- DoorDash = not an official website
- Uber Eats = not an official website
- Grubhub = not an official website
- OpenTable = not an official website

| Active business | 10 |
| Phone | 5 |
| Email | 5 |
| Social | 5 |
| Owner/decision maker | 5 |

| Multi-source verification | 5 |
| **Total** | **100** |

Digital opportunity label:

- HIGH DIGITAL GAP
- MEDIUM DIGITAL GAP
- LOW DIGITAL GAP

This is an opportunity signal, not a guarantee that the restaurant will buy a website.

# 14. SECURITY

## Google API

- Store API key server-side.
- Never expose secret keys in frontend code.
- Use environment variables.
- Restrict API key permissions.
- Enable only required APIs.
- Never commit secrets.

## Website Verification

Implement SSRF protection:

- Block localhost
- Block private IP ranges
- Block internal services
- Validate DNS
- Limit redirects
- Limit response size
- Set request timeout
- Validate URL scheme
- Handle TLS errors

## Authentication

Use production-grade authentication.

Every protected mutation requires server-side authorization.
